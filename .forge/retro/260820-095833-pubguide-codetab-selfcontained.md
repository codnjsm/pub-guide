# 2026-08-20 — 코드 탭을 복붙 가능한 완성 컴포넌트로 전환

## Plan vs actual
- What went as planned: 6개 슬라이스 전부 착지. 8개 뷰의 코드 탭이 `<script setup>`+`<template>`+`<style scoped>` 형태가 됐고(`CardsView`는 원본에 style이 없어 2블록), `viewport`는 전부 `useDisplay()`로 치환됐다. README 규칙 교체, 외부 파일 안내 4곳, 부수 정리(빈 슬롯 래퍼·폴더 트리 누락)까지 완료. 빌드/린트 통과.
- Divergences: **`</script>` 함정 1건.** 코드 탭이 `<script setup>` 블록을 통째로 담게 되니 문자열 안의 닫는 태그에서 Vue SFC 파서가 스크립트 블록을 끊어 파일이 깨졌다. 1차 생성분을 `git checkout -- src/views/`로 되돌리고 생성기에 `</script>` → `<\/script>` 이스케이프를 넣어 재생성했다.
- 사소한 사고: 앞선 조사 단계의 `cd src/views`가 셸에 남아 첫 생성이 `FileNotFoundError`로 실패 — 절대 경로로 해결.
- 계획서에 따로 적었던 "경미한 불일치도 함께 해소"(HeroView 줄바꿈, NavigationView `v-btn` 포맷)는 **생성기가 실제 템플릿에서 추출하므로 자동 해소**됐다. 별도 작업이 필요 없었다.

## Learnings

### 1. 코드 탭 문자열 안의 `</script>`는 이스케이프한다 (README로 승급)
Vue SFC 파서는 `<script>` 블록을 **첫 `</script>`에서** 끝낸다. 코드 탭이 Vue 파일 전체를 담게 된 이상 닫는 태그가 반드시 문자열 안에 들어가므로, `<\/script>`로 써야 한다. JS 템플릿 리터럴에서 `\/`는 `/`이므로 화면에는 `</script>`로 정상 표시된다. 앞으로 코드 탭을 손으로 고칠 때마다 재발할 수 있어 README에 올린다.

### 2. 규칙을 엄격하게 만들면 강제 수단도 같이 만들어야 한다 (후속 과제로 승격)
이번 변경의 진짜 비용은 코드가 아니라 **유지 비용**이다. 전에는 템플릿 한 줄 고치면 코드 탭도 한 줄 고치면 됐는데, 이제 코드 탭은 3블록이고 FullMenu는 420줄이다. 앞으로:
- script의 데이터를 바꿨는데 코드 탭에 반영 안 함 → 조용히 어긋남
- style을 추가했는데 코드 탭 style 블록엔 없음 → 복붙하면 모양이 다름

지금 이걸 막아주는 건 scratchpad에 있는 일회용 생성기뿐이고 커밋도 안 돼 있다. **규칙은 엄격해졌는데 강제 수단이 없는 상태.** 이대로 두면 이번에 세운 규칙이 몇 달 안에 무너진다.

일반화하면: **"항상 동기화하라"는 규칙을 세울 때, 동기화 대상이 손으로 유지 가능한 크기인지 먼저 따진다. 아니면 규칙과 함께 도구를 낸다.**

## 후속 과제 (승인됨 — 별도 loop으로)
- **코드 탭 생성기를 프로젝트에 정식 편입**: `scripts/gen-codetab.mjs` + `npm run codetab`. 이번에 만든 `VIEWPORT_MAP` 치환과 `<\/script>` 이스케이프를 그 안에 유지한다. 검증만 하는 방식(어긋남 검사)은 검토했으나 기각 — 어긋난 걸 알려줘도 결국 사람이 420줄을 손으로 맞춰야 한다.
