# 2026-08-20 — 히어로 배너 전면 교체 (+ 코드탭 생성기 결함 다수 발견·수정)

## Plan vs actual
- What went as planned: fg-visual로 확정한 시각값(비율, 폰트, 텍스트 위치, 플레이스홀더)은 전부 그대로 반영됐다. `viewport` 분기, 코드 탭 규칙, 빌드/린트 모두 계획대로.
- Divergences (컸다):
  1. **breadcrumb을 Non-goals에서 뺀 판단이 틀렸다** — 마크업 조각에 없다고 단정했는데, 사용자가 개발자도구 캡쳐로 KV 안에 있음을 보여줘 실행 후 추가했다.
  2. **실행 중 생성기 결함 2건** — 빈 줄 매달림, 그리고 **스타일 블록을 코드 문자열 안 낡은 사본에서 읽어 실제 스타일 변경이 반영 안 되던 결함**(검사기가 어긋남을 숨기는 상태).
  3. **적대적 리뷰에서 생성기 결함 4건 추가** — 자리표시자 함정 미방어, 정규식 실패 시 조용한 스킵, viewport 잔존 미검사, 백슬래시 미이스케이프. 전부 재현 테스트로 확인 후 수정.
  4. **적대적 리뷰 워크플로우 자체의 진행 문제** — 세션 사용량 한도로 검증(반박) 단계 다수와 렌즈 하나가 실패. 자동 집계 스크립트가 검증 못 받은 발견을 결과에서 조용히 빠뜨리는 버그가 있어, 워크플로우 저널에서 원본을 복구해 직접 재현·검증했다.

## Learnings

### 1. `replace_all: true`를 믿지 말고 재현 테스트로 확인한다 (승급하지 않음)
자리표시자 함정을 고칠 때 같은 정규식이 파일 안 두 곳(`buildCode`와 `render`의 `kept` 계산)에 있었다. `replace_all: true`로 한 번에 바꿨다고 생각했는데, 실제로는 한 곳만 바뀌었다 — 도구의 "성공" 메시지만으로는 몰랐고, **직접 재현 테스트를 돌려봐서야** 발견했다.

규칙: **버그를 고쳤다고 판단하는 기준은 "편집 도구가 성공을 보고했다"가 아니라 "재현 시나리오를 실제로 돌려서 확인했다"여야 한다.** 이번엔 정확히 그렇게 했고(4건 전부 재현 스크립트로 검증), 그 과정에서 놓친 두 번째 사본을 잡았다.

### 2. 리뷰 워크플로우는 검증 실패(null)를 명시적으로 추적해야 한다 (승급하지 않음)
적대적 리뷰 워크플로우가 세션 한도로 검증 단계 다수를 실패했는데, 집계 로직이 `f.verdict && !f.verdict.refuted`(생존)와 `f.verdict && f.verdict.refuted`(반박)만 필터링해서 `verdict`가 `null`인 발견은 **어디에도 안 잡히고 조용히 사라졌다.** 워크플로우 저널을 직접 뒤져서 복구했으니 망정이지, 그러지 않았으면 critical 결함 여러 건이 통째로 누락될 뻔했다.

규칙: **워크플로우에서 하위 에이전트 실패(null 반환)가 있을 수 있는 필터는, 실패 케이스를 별도로 세어 보고한다.** "no silent caps" 원칙이 검증 단계 자체의 실패에도 적용돼야 한다.

### 3. breadcrumb 판단 오류 (승급하지 않음 — 기존 패턴의 반복)
"마크업 조각에 없으면 밖에 있는 것"이라고 단정한 게 원인. 이전 회고들에서 이미 여러 번 나온 "시각적 판단은 눈으로 확인 없이 단정하지 않는다" 계열이라 새로 적지 않는다.
