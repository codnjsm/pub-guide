# 2026-08-20 — Cards 섹션 전면 교체 (최종: 일반화된 카드 그리드)

## Plan vs actual
- What went as planned: 1차 실행(계획서 그대로 — 8개 카테고리, 실제 차량 데이터, button/a 구조 구분)까지는 이탈이 없었다.
- Divergences (컸다): 1차 UAT 이후 8차례 피드백 라운드를 거치며 결과물이 근본적으로 달라졌다.
  1. 호버 배경이 안 보인다는 피드백 — 처음엔 "영역이 좁다"고 오진단했다가, 실제로는 `CodePreview.vue`의 프리뷰 캔버스 배경(`#f6f3f2`)과 카드 호버 색이 같아서였음을 뒤늦게 발견.
  2. 정사각형 카드 + 이미지/이름/가격 순서 + 클릭 시 새 탭 이동 요청 — button/a 구조 구분을 걷어내고 `<a target="_blank">`로 통일.
  3. 실제 hyundai.com URL 추가 → 곧바로 제거 요청.
  4. 실제 차량 데이터 → `Category N`/`titleN`/`subtitleN`/`badge`/`description`/`link`로 완전 일반화.
  5. 배지 값이 boolean → 카드마다 다른 문자열로.
  6. 카테고리 8개·아이템 17개 → 3개·6/5/7개(총 18개)로 축소.
  7. 부수 사고: 편집 중 "N" 카테고리가 한 번 통째로 유실됐다가 복구, 이후 카테고리 축소 요청으로 다시 사라짐(결과적으로 문제 없음).

## Learnings

### 1. 공유 인프라 스타일을 먼저 확인하지 않고 로컬 버그로 오진단했다 (승급 — 회고 로그)
"호버가 안 보인다"는 신고에 카드 자체의 패딩/영역만 늘렸는데, 실제 원인은 이 프로젝트가 색·간격 값을 공유 컴포넌트(`App.vue`, `CodePreview.vue`)에 몰아두는 구조라서, 개별 뷰가 그 공유 틀 위에 얹힐 때 **같은 색을 우연히 재사용하면 시각적으로 상쇄**될 수 있었던 것이다. 두 라운드를 낭비한 뒤에야 `CodePreview.vue`를 열어보고 발견했다.

규칙: **한 컴포넌트의 시각 버그(특히 "색이 안 보인다"류)를 진단할 땐, 그 컴포넌트가 렌더링되는 공유 틀/부모 컴포넌트의 배경·오버레이 스타일부터 먼저 확인한다.** 이 프로젝트에서 이미 3번 반복된 `@layer` 우선순위 함정과 같은 계열 — "이 로컬 요소가 왜 이상하게 보이나"의 원인이 로컬이 아니라 공유 레이어에 있을 수 있다는 걸 먼저 의심해야 한다.

### 2. 그릴링 때 시각 요구사항 묶음을 한 번에 안 물었다 (승급 — 회고 로그)
"정사각형·이미지→이름→가격 순서·호버·클릭 시 새 탭"은 원래 그릴링 단계에서 한 번에 확정했어야 할 시각 요구사항 세트였는데, 실행이 끝난 뒤 사용자가 화면을 보며 하나씩 요청하는 형태로 나왔다. 바로 앞 과제(#22 히어로)에서는 fg-visual로 이런 시각 요구사항을 한 번에 확정하는 체크포인트를 지켰는데, 이번엔 그 판단을 건너뛰었다 — "카드 섹션"이라는 이름만 보고 저위험 작업으로 짐작한 게 원인으로 보인다.

규칙: **"OO을 다시 잡자/OO 모양으로 바꾸자"류 재설계 요청이 실행 후 UAT 단계에서 들어오면, 그 시점에 fg-visual 제안을 다시 검토한다** — "이미 실행했으니 그냥 텍스트로 계속 고치자"는 관성에 빠지지 않는다.

### 3. "실제 데이터 → 완전 일반화"는 방향 전환 신호였다 (승급하지 않음 — 이번 1회 사례)
이 컴포넌트를 "실제 콘텐츠 예시"로 쓸지 "순수 UI 패턴 예시"로 쓸지는 이 프로젝트의 다른 섹션(Header/GNB, Footer 등 전부 실제 hyundai.com 콘텐츠 사용)과 대비되는 선택이었다. 아직 한 번뿐인 사례라 패턴으로 부르기엔 이르다 — 다음에 비슷한 "일반화해줘" 요청이 나오면 그때 회고 로그를 넘어 승급을 검토한다.
