## Learnings

### ① 완료조건에 작업 트리 상태를 걸지 않는다 (승급하지 않음)
S2의 완료조건을 "재생성 후 `git diff`가 비어 있음"으로 잡았는데, 직전 과제(#19)의 변경이 아직 커밋되지 않은 상태라 **애초에 성립할 수 없는 조건**이었다. 실행 시점에 발견해 "재생성 직전 `src/views/`를 스냅샷으로 복사 → `diff -r`로 바이트 비교"로 대체했고, 이쪽이 git 상태와 무관해 오히려 더 견고했다.

규칙: **완료조건은 그 시점의 작업 트리/커밋 상태에 의존하지 않게 쓴다.** `git diff`, `git status` 기반 판정은 "지금 트리가 깨끗한가"라는 숨은 전제를 깔고 있다. 이 프로젝트는 커밋을 명시 요청 시에만 하므로 트리가 지저분한 게 정상 상태에 가깝다 — 전제가 거의 항상 깨진다.

### ② 재구현은 "동작한다"가 아니라 "기존과 바이트 동일"을 완료조건으로 (승급하지 않음)
이번에 실제로 밟을 뻔한 함정: **파이썬 `str.replace`는 모든 occurrence를 치환하지만 JS `String.replace`는 첫 항목만 바꾼다.** `HeaderView`의 `viewport === 'desktop'`이 2곳이라, 그대로 옮겼으면 한 곳만 치환된 채 **빌드도 린트도 통과하고 화면도 멀쩡했을 것이다.** 코드 탭 안쪽 문자열이라 눈으로도 안 보인다. 이런 종류는 바이트 비교만이 잡는다.

규칙: **기존 산출물이 이미 있는 것을 재구현할 때는 완료조건을 "돌아간다"가 아니라 "기존 산출물과 바이트 단위로 같다"로 잡는다.** 이번엔 S2를 별도 슬라이스로 분리해 이 조건을 못박은 판단이 값을 했다. 앞으로 `gen-codetab.mjs`를 고칠 때도 같은 검증이 필요하다(스냅샷 → 재생성 → `diff -r`).
