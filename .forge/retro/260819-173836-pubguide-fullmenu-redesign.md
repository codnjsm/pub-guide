# 2026-08-19 — 전체메뉴 오버레이 전면 교체

## Plan vs actual
- What went as planned: 5개 슬라이스 모두 착지. 6개 탭·30개 카테고리 데이터, 어두운 탭 바, 탭 클릭 시 `scrollIntoView` 스크롤 이동, 600px 고정 높이 내부 스크롤, 코드 탭 동기화, 빌드/린트 통과.
- Divergences: 결과물은 계획대로지만 **경로가 크게 이탈** — 실행 후 사용자 피드백으로 6라운드 수정이 붙었다. 두 갈래로 나뉜다.
  1. **치수/배치 오차(4라운드)** — 캡쳐만 보고 추정한 검색 인풋 폭이 실제와 달랐고(실제는 `width: 48.58%; min-width: 480px; padding: 80px 0 0`), 3depth 링크를 "카테고리 블록을 세로로 쌓고 링크를 세로 나열"로 만들었는데 실제는 **카테고리 제목이 왼쪽 고정 컬럼이고 링크가 오른쪽에서 가로로 흐르는** 구조였다.
  2. **기능 결함(1건)** — X 버튼이 마크업만 있고 핸들러가 없어 동작하지 않았다.
- 계획 범위 밖 시도 1건: 프리뷰 배경(`CodePreview.vue`)을 `#e5e5e5`로 바꿨다가 사용자 요청으로 원복 — 최종 상태 변경 없음.

## Learnings

### 1. 치수가 중요한 요소는 그릴링 단계에서 실제 CSS를 콕 집어 요청한다 (승급하지 않음)
`48.58%` 같은 값은 캡쳐에서 절대 역산할 수 없다. 이번에 검색 인풋 폭 하나에 3라운드를 썼다. 다만 "무조건 CSS부터 달라"는 과하다 — fg-ask 그릴링에서 **"이 요소는 폭/여백이 픽셀 단위로 중요해 보이는데 실제 CSS 있으면 주세요"라고 해당 요소만 지목해 묻는다.**
직전 검색 패널 회고에서 "캡쳐 기준으로 맞춘 뒤 눈으로 보며 미세 조정은 정상 흐름"이라고 결론냈는데, 이번 건은 그 범주를 넘었다. 미세 조정이 아니라 **구조가 틀렸다.** 정상 흐름의 경계는 "치수 미세 조정"까지고, 레이아웃 방향(세로↔가로) 같은 건 캡쳐 판독 실패로 본다.

### 2. 계획서에 인터랙티브 요소별 동작을 한 줄씩 명시한다 (승급하지 않음)
계획서는 상단 요소를 "검색 입력창, 닫기(X) 버튼"이라고 **나열**했지만, 인터랙션 슬라이스(S4)는 스크롤 이동만 정했다. 그래서 X 버튼이 장식으로 남았다. 검색창은 Non-goals에 "검색 동작은 구현하지 않는다"고 적혀 있어 사고가 없었다 — **차이는 '동작을 적었는가'였다.**
슬라이스를 늘리는 게 아니라 Goal 항목에 한 줄씩 붙이는 정도로 충분하다: `닫기(X) 버튼 — 클릭 시 패널 닫힘 / 검색 입력창 — 입력 UI만, 검색 동작 없음`.

### 3. 패널 토글 패턴 (README로 승급)
X 버튼을 오버레이 안 우측 상단에 절대 배치하고 닫히면 중앙에 "전체메뉴 열기" 버튼을 띄우는 방식을 먼저 만들었다가, 사용자가 "검색패널처럼 해달라"고 해서 갈아엎었다. SearchSuggestView가 이미 쓰고 있던 **패널 밖 토글 버튼 + `:icon` 삼항 + `v-expand-transition`** 이 이 프로젝트의 패턴이다. 두 곳에서 같은 모양이 됐으므로 README에 승급한다.
승급 판단 근거: 앞으로도 "열리는/닫히는" 섹션이 계속 추가될 성격이고, 그때 참고할 자리가 필요하다. README의 "스타일링 규칙"은 이름이 안 맞아 **"인터랙션 패턴" 섹션을 새로 만들었다.**
